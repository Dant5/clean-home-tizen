# Q60B functional review — 19 November 2026

Scope: functionality and reliability for QA55Q60BAWXXY / Tizen 6.5 / firmware 1720.7. No visual redesign, new themes/fonts/backgrounds, native changes or TV deployment. DNS work remains separate on PR #20.

The installed **1.3.9 / 7d2109e** is distinct from public main **67090df / source 1.4.3**. The retained installed lineage and current main have the same input-switch implementation: enumerate `VIDEOSOURCE`, select the reported type/number, then hide only Clean Home. Both allow selecting a disconnected port. Main additionally contains the public app chooser, compatibility/reporting and setup work; those source features are not assumed installed.

## Decisions

| Area / problem | Existing Clean Home vs upstream | Decision and implications | Evidence still needed |
|---|---|---|---|
| **Late HDMI completion steals focus** | Both installed lineage and main can call `hide()` after the operation timed out; UI callback invalidation alone does not prevent that native side effect. CleanFrame/AeroTizen guard later stages. | **Implemented:** one total deadline, explicit cancellation, supersession, Back/blur/suspend invalidation, optional selected-source validation and exactly-once completion. No new idle work, privilege, dependency or stored preference. | Adapter tests cover timeouts between phases, late callbacks, replacement, wrong input and synchronous blur/hide failure. Browser tests exercise real Back/blur routing. Physical Q60B rehearsal remains pending. |
| **Sleeping/disconnected HDMI / CEC wake** | Clean Home already includes disconnected ports and re-enumerates on every selection. AeroTizen retains recognised standby entries and attempts switching so CEC can wake them. | Existing selection behavior is equivalent in the important respect: do not reject a port solely because it lacks signal. No explicit CEC wake guarantee, guessed port fallback or repeated native commands added. | Console asleep, powered off and unplugged; select once, observe wake/signal/audio and return Home. A returned callback is not proof of signal. |
| **Native viewer / disconnected recovery** | AeroTizen now prefers its native viewer helper; tidyTizen tries viewer then embedded video. Our reference setup uses public `setSource` plus launcher hide. | Keep the working Q60B handoff. Importing a different helper/service or embedded video would introduce Home/Back/overlay/audio risks without evidence our existing handoff fails. Current fix prevents late hide; it cannot undo a `setSource` already accepted by Samsung. | Physical source switching from another app, loss/recovery of signal, CEC/eARC and Home return. Compare an alternative only if a specific reproducible failure remains. |
| **Input status refresh / naming** | CleanFrame refreshes chooser status on return; AeroTizen uses events plus foreground refresh and `editName`. Our list refreshes when reopened and before selection, but an already-open list can be stale on resume; labels are generic. | Useful follow-up, **not included** in the cancellation fix. Qualify `editName` and any event listener on this firmware first. Prefer on-demand/return refresh and bounded labels over an idle poller or guessed device names. Local aliases must not rename native Samsung inputs. | Getter samples for named/sleeping/unplugged devices, listener cleanup and focus preservation when a list changes. No new settings/layout required before the data is trustworthy. |
| **Remote navigation / focus** | Existing code already coalesces repeats, clears held keys on blur/suspend, cancels long-press selection, preserves one focus and restores the dock on native relaunch. | Retain existing behavior. Add input-operation cancellation to these existing lifecycle boundaries; no visual/focus-style change. Avoid a navigation framework rewrite. | Current/85 regression suite plus physical rapid Back, held Select, native Home return and immediate wake arrows. |
| **Application launch / stale registry** | Our discovered/manual IDs, five-minute persisted catalogue, deduplicated enumeration, 20-second registry timeout and bounded launch errors exceed upstream hard-coded favourite tables. | No replacement. Preserve ambiguity handling and sideload bindings. A public launch request already issued cannot generally be recalled; callback cancellation must not claim otherwise. | Existing tests cover missing/ambiguous/hidden apps, save errors, cache expiry and late enumeration. Physical owner app launches remain the reference baseline. |
| **Home / startup** | Our Q60B already has working rootless native assignment, exact guards, saved originals and Undo. arn0-tv documents analogous per-TV native mechanisms; AeroTizen has broader watcher/root paths. | No native change, watcher, root component or reassignment. The installed original settings and recovery identity remain authoritative. A different TV's success is not a reason to rewrite this TV's Home configuration. | Existing hardware audit is retained. Any future helper change needs separate baseline/readback/partial-failure/Undo qualification and owner approval. |
| **Continue Watching** | AeroTizen discovers declared Samsung metadata and reads a local EBHelper feed; its Stremio provider separately requires root. Clean Home has no equivalent feed UI. | Feasible research **without assuming root is necessary**, but not a justified reliability patch. Nuvio Legacy/Moonlight feed support and correct programme deep links are unverified. Adding a Home row would conflict with the requested unchanged layout. No credentials, viewing history, feed polls or root provider added. | Opt-in per-app metadata/feed availability, malformed/empty/stale results, cancellation, memory/privacy bounds and actual title deep links. Decide an existing-screen presentation separately if real useful data exists. |
| **Updates / diagnostics** | Current main already has opt-in sanitised TV/setup reports, failure codes, exact Home-write guard, unsigned generic release boundaries and owner signing. AeroTizen's IP Control logging applies to a subsystem we do not use. | Retain existing reporting and reviewed updates. Do not add unused IP Control/root/update mechanisms or raw support logs. App updates and Samsung firmware policy are separate; no firmware/update settings changed. | Hosted current-head checks, source/history scans and same-author install/rollback before any future approved deployment. Native transport problems remain tracked separately. |
